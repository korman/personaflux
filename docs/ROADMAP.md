# 实施路线图

## 粗略工作量

| 阶段 | 单人估算 |
|---|---:|
| 纯 Rust 核心 MVP | 3 到 5 周 |
| 关系、记忆、传闻和存档 | 3 到 5 周 |
| 稳定 C ABI 和头文件 | 2 到 3 周 |
| C#、Swift、Kotlin 绑定 | 3 到 5 周 |
| iOS、Android 和 CI | 2 到 4 周 |
| 文档、压力测试和 ABI 加固 | 3 到 5 周 |

可调用 MVP 约 2 到 3 个月；适合公开发布的跨平台稳定版本约 4 到 6 个月。

## 阶段 0：启动

- 检查名称占用和商标。
- 建立 workspace、许可证、CI 和 ADR 模板。
- 固化项目章程和独立实现规则。

## 阶段 1：行为规格

- 决定 PAD 和关系数值范围。
- 决定关系层级与继承。
- 定义 Deed、Rumor 和 Memory schema。
- 独立设计评价公式和至少 12 组固定向量。
- 明确事件顺序和确定性。

退出条件：实现者无需查看 Love/Hate 源码即可根据规格实现算法。

## 阶段 2：Rust 核心

- 完成阵营、成员、有向关系、PAD 和情绪区域。
- 实现纯评价函数、原子提交和事件队列。
- 添加单元测试和属性测试。

## 阶段 3：记忆与传闻

- 容量、过期、去重和习惯化。
- 传闻传播、置信度、逻辑时间和随机源。
- 建立性能基准。

## 阶段 4：快照

- 配置 schema、版本化快照、往返测试和迁移基础。

## 阶段 5：C ABI

- 不透明句柄、头文件、批量命令、事件读取、错误码和 panic containment。
- C 示例和 ABI 测试。
- 先发布 ABI v0，经过多语言验证后冻结 v1。

## 阶段 6：桌面绑定

- Windows、Linux、macOS 产物。
- C# SafeHandle、可选 C++ RAII 和 Unity 示例。

## 阶段 7：移动端

- iOS XCFramework 和 Swift 包装。
- Android 多 ABI、JNI/Kotlin 和 AAR。
- 真机生命周期与性能测试。

## 阶段 8：公开发布

- crates.io、GitHub Releases、文档、示例、支持矩阵和迁移说明。
- 冻结 ABI v1 和快照 v1。

## 主要风险

| 风险 | 缓解方式 |
|---|---|
| 行为不清导致重写 | 先完成规格和测试向量 |
| 许可证风险 | 独立实现、来源记录和评审 |
| ABI 过早冻结 | 先稳定核心，再发布 ABI v1 |
| FFI 过细 | 批量命令和事件队列 |
| 浮点差异 | 明确确定性承诺和平台测试 |
| 移动端生命周期错误 | 不透明句柄和包装层测试 |
| 回调、多线程过早复杂化 | 第一版轮询事件和单线程提交 |
